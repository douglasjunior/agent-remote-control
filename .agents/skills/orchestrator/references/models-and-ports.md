# Models, Ports and Services

The models, ports and supporting services of the orchestrator, one by one. Read when changing a model or a port contract, the session or settings stores, or one of these services.

## Core Models

The models live in `packages/server/src/modules/orchestrator/models/`:

### `SessionContext` (`session-context.model.ts`)

Cache of the ACP sessions of a conversation. It contains only serializable data; the execution state
(live agents, queue, active turn) belongs to `ConversationRuntimeService`:

- `conversationId`: unique conversation identifier (generated by the channel or client), also the key under which the store keeps it;
- `agentSessions`: list of `AgentSession` (`agent-session.model.ts`: `role`, `agentId`, `sessionId`, `projectName`, `artifactId`, `workEndedAt?`, `unanswered?`) with the ACP session of each role (CEO and delegates) in each agent, project and task, at most one per role/agent/project/artifact, used to resume them with `loadSession`. `projectName` is `null` for whoever runs at the workspaces root (the CEO and delegations without a folder); since it is part of the key, a role's history in one project is never resumed in another. `artifactId` is the task of a delegation with an artifact and `null` for work without one, so a role keeps one session per task plus one per project for the rest. Returning to an agent already used in the conversation resumes its session. A new session starts with an empty list. `workEndedAt` is the moment the last delegation in that session on its artifact ended, whatever its outcome, provided the agent answered a prompt of it (`AgentRoundService.recordWorkEnded`, called in the delegation's `finally` while its port still holds the session): the binding is the record of what the session last saw, so a session resumed later is told what changed on the artifact from then on. A delegation whose prompts all failed may have shown the session nothing, so the earlier moment stands. A binding created for a new session has none until its work ends. `unanswered: true` marks a binding from the creation of its session until the agent shows itself at work on a prompt in it (a `thought` or `tool` activity, or the prompt ending), which `AgentRoundService` records at that first sign: the session is stored before its first prompt so that a restart can resume it, and nothing says the instructions of an unanswered one reached the agent, so loading it gives the state `new`.

### `TurnRequest` (`turn-request.model.ts`)

Encapsulates the parameters for running an interaction round:

- `conversationId`: identifier of the requesting conversation;
- `userId`: author of the prompt;
- `prompt`: instruction sent by the user;
- `workspacePath`: local working directory associated with the turn;
- `agentRole`: root role that receives the prompt (e.g. `'CEO'`);
- `attachments`: optional list of `TurnAttachment` (`turn-attachment.model.ts`: `name`, `path`, `contentType`, `size`, `url?`) with files received and downloaded locally;
- `onActivity`: optional callback `(activity: TurnActivity, role: string) => void` (`turn-activity.model.ts`) that streams the activities of every agent of the turn, each with the role of the agent that produced it, the response protocol already read;
- `onDraft`: optional callback `(text: string) => void` with the part of the CEO's response that the user reads, as far as it is written: whole at every call (replaced by the next one, so a channel keeps only the last), empty when discarded. The protocol tags (`<delegate>`, `<question>`, `<attachment>`, `<user_language>`) and a tag still being typed are left out (`AgentProtocolService.visibleReply`). The finished response reaches the channel through the result, `onInterimMessage` or `onQuestion`; the orchestrator discards the draft (`''`) before asking the CEO to repair a response. Answers written by delegated agents never reach it;
- `onQueued`: optional callback `() => void` called when the turn is queued behind another turn of the same conversation.
- `onInterimMessage`: optional callback `(message: string) => void`, called with the `message` of a CEO response that delegates, when not empty, before the delegations start.
- `onQuestion`: optional callback `(event: QuestionEvent) => void` (`question-event.model.ts`), called with `{ kind: 'asked', prompt }` when an agent of this turn asks and the question reaches the front of the conversation queue on its own, and with `{ kind: 'timedOut', asker, answered, timeoutMs, next? }` when the user did not answer in time (see "Questions to the User").
- `onDelegation`: optional callback `(event: DelegationEvent) => void` (`delegation-event.model.ts`), called with `phase: 'started'` before the delegate works, `phase: 'steered'` when the CEO sends the running agent a new instruction (`taskSpec` is that instruction and `summary` its summary, which the events after it carry too), `phase: 'finished'` when it completes successfully and `phase: 'failed'` (with `errorMessage` and `durationMs`) when it stops with an error and `phase: 'cancelled'` (with `durationMs`) when it is cancelled, so that a delegation still open afterwards can only be one a restart stopped; carries `delegationId` (a UUID generated once per run of a delegation, the first one being the id that holds its artifact, and shared by all its phases, because `round` restarts in each turn and cannot identify a delegation; a follow-up run in the same session has its own), `round`, `role`, `roleName`, `projectName?`, `artifactId?` (the artifact the agent holds) and `summary` (the plain-language `summary` attribute of the `<delegate>` tag, required, whitespace collapsed and cut at 120 characters; a `<delegate>` without it is an invalid response the CEO is asked to repair) and `taskSpec` (the task as the CEO wrote it). `finished` also carries the delegate's `response`, `agentInfo`, `usage` (the token usage of every prompt of the delegation added up, absent when none reported it) and `durationMs`.

### `ActiveTurn` (`active-turn.model.ts`)

Represents a conversation's running turn:

- `activate(agentPort)`: registers the agent that is running (CEO or delegate);
- `cancel()`: marks the turn as cancelled and calls `cancel()` on the active agent;
- `reset()`: resets the cancellation state to false;
- `throwIfCancelled()`: throws `PromptCancelledError` if the turn was cancelled. The orchestrator calls it before `connect`, after `connect` and before each `prompt`, so that a cancellation requested while the agent is still connecting interrupts the turn.

### `ActiveDelegation` (`active-delegation.model.ts`)

Represents a technical delegation currently running in the background:

- `delegationId`: the id that holds its artifact on the board;
- `role`: role of the delegated agent;
- `roleName`: readable role name;
- `projectName`: target project/directory of the task or `null`;
- `summary`: the summary of the last instruction the agent received;
- `taskSpec`: the task as first delegated;
- `cwd`: the delegate's working directory;
- `startedAt`: start timestamp;
- `agentPort`: `IAgentPort` instance of the delegated agent;
- `turn`: `ActiveTurn` instance associated with the delegate's execution;
- `control`: its `DelegationControl` (below);
- `stop(reason)`: ends the work before it finishes without ending the turn; the CEO receives `reason` as a result with `status="stopped"`.

### `DelegationControl` (`delegation-control.model.ts`)

What reaches a running delegation between its prompts. `runId` is the event id of the run in progress and
`contextSince` the moment the agent was last told what changed on its artifact; `summary` and `updates` hold the
instructions it received after its task (`record`). `keep(instruction, interrupt?)` keeps one for the next prompt and
`take()` hands them to the prompt being written; `takeInterruption()` says once whether a prompt was cancelled to
deliver them; `seal()` ends the run when nothing is kept, after which `acceptsInstructions` is false and `keep` refuses.
`follow`, `withdraw` and `next` queue, take back and start follow-ups (`FollowUp`: the instruction, the turn that sent it,
its round and `settle`); `next` with none left closes the delegation to new ones. `addWaiter` counts a delegation
waiting for this one (`queued` adds them to the follow-ups), `close()` hands back the follow-ups that never ran, and
`finish(end)` resolves `ended` with how it ended (`DelegationEnd`: `finished`, `failed`, `stopped`, `replaced` or
`cancelled`).

### `ValidatedDelegation` (`validated-delegation.model.ts`)

A delegation that passed every check, with the `cwd` its agent runs in, plus, for work resumed after a restart, the `workId` it continues, the `firstPrompt` it receives in place of the task, the `updates` it had received and the `answerDelivery` (`AnswerDelivery`, with the task and its updates) carrying answers the agent asked for before the restart. `ValidatedDecision` is the CEO decision with its delegations validated.

### `TurnResult` (`turn-result.model.ts`)

Immutable structure with the turn outcome:

- `response`: consolidated final text response;
- `status`: `'completed'` on success, `'cancelled'` if interrupted, `'failed'` if aborted by an error, or `'steered'` when another turn carries on (a prompt injected into the CEO round already in progress, or a turn whose agents were replaced or took its instructions into a run another turn waits for), with the response coming from that turn's result, so `response` is empty and there is no `usage`);
- `usage`: token usage of the CEO's last round (`getLastRoundUsage()`); absent when the agent does not report it or collection fails;
- `errorMessage`: error message present exclusively in failed outcomes;
- `agentInfo`: `TurnAgentInfo` (`roleName`, `agentName`, `modelName?`, `effortName?`), filled in all three statuses so the channel can show which agent, model and effort generated the response;
- `attachments`: optional list of absolute paths of the final response's `<attachment>`s, resolved by `ExecuteAgentTurnUseCase` through `IFileSystemPort.isReadableFile`: relative paths start from `workspacePath`, the `file://` prefix is accepted, and only existing regular files are included, without duplicates.

### `AgentSettings` (`agent-settings.model.ts`)

Configuration of a conversation: `profiles` (role → `AgentProfileSettings`), `appliedSquad?` (`{ id, name }` of the
squad last copied in, kept after the squad is deleted) and `updatedAt`.
`AgentProfileSettings` holds `agentId`, `agentName` (catalog display name), `modelId`, `modelName`,
`effortId` and `effortName`. `modelId === null` indicates an agent without published models;
`effortId === null`, a model without effort levels.

`utils/agent-profile.util.ts` holds the pure rules on profiles: `resolveProfile(settings, role)`
returns the role's profile, falling back to the `CEO` profile, and `profileForAllRoles(roles, profile)` builds the
role → profile record. Stamping `updatedAt` belongs to `AgentProfilesService.save`, which reads the clock.

### `AgentOption` and `AgentRoleProfile`

`AgentOption` (`agent-option.model.ts`) is a neutral choice with `id`, `name` and `description?`: an agent, a model or an effort. It has no index; numbering is a menu concern of the channel. `AgentRoleProfile` (`agent-role-profile.model.ts`) is one role of a conversation: `role`, `roleName` and, when the conversation has settings, its `profile` and `agentAvailable`.

## Orchestrator Ports

The orchestrator ports live in `packages/server/src/modules/orchestrator/ports/`:

### 1. `ISessionStorePort` (`session-store.port.ts`)

Responsible for persisting and querying session state:

- `findSession(conversationId: string): Promise<SessionContext | null>`
- `updateSession(conversationId: string, change: SessionChange): Promise<SessionContext>`: `change` receives the stored
  session, an empty one when there is none, and returns the session to store or `undefined` to leave it; the whole
  read-change-write is one step under the file's lock, so the bindings that parallel delegations change at once all stay.
  `AgentRoundService` binds and stamps agent sessions only through it, and `resolveSession` creates the empty session of a
  new conversation with it.
- Symbol of the same name: `export const ISessionStorePort = Symbol('ISessionStorePort');`

The implementation is `SqliteSessionStoreAdapter` (see the `database` skill): a `session` row per conversation, kept
while it has no bindings, and an `agent_session` row per binding in list order (`work_ended_at`, and `unanswered` set
only while true). `updateSession` reads, changes and replaces the conversation's rows in one
`SqliteTransactionService.run`, so other processes never interleave either. The `sessions` legacy importer reads
`DATA_DIR/sessions.json`, the map `{ [conversationId]: { agentSessions } }` or the earlier array of items
(`conversationId`, or `channelId` with an optional `threadId`), ignoring every other field; when items share a
conversation id, the later one wins, entries without a text `agentId` are dropped and a missing `projectName` or
`artifactId` is `null`. Specs
use the `InMemorySessionStoreFake` from `testing/`, seeded with `seed(session)`.

### `ISpeechToTextPort` (`speech-to-text/ports/speech-to-text.port.ts`)

`isEnabled(): boolean` and `transcribe(audioPath, { language? }): Promise<string>` (empty text when there is no speech; rejects on failure). It belongs to the `speech-to-text` module, imported by `OrchestratorModule`. `SpeechToTextModule` binds the port with a factory that picks the adapter named by the `STT_PROVIDER` setting (`whisper-cpp`, the default, or `none`) once, as the server starts, so changing it applies on restart; `selectSpeechToTextProvider` throws with the supported list for a name its map lacks. `WhisperCppAdapter` runs on CPU: `ffmpeg` converts the file to 16 kHz mono WAV, then `whisper-cli` writes the transcript (`STT_MODEL`/`STT_MODEL_PATH`, `STT_LANGUAGE`, `STT_THREADS` with `0` for every CPU, `STT_TIMEOUT_MS`, `STT_WHISPER_BIN`, `STT_FFMPEG_BIN`, read from `IRuntimeSettingsPort` on every transcription); it runs both through `IProcessRunnerPort.run(command, args, { signal })`, whose signal enforces the timeout, and removes its temporary files. `NoopSpeechToTextAdapter` reports `isEnabled() === false`. A new provider (for example a GPU one) is a new adapter plus one entry in `selectSpeechToTextProvider`'s map. Specs use `StubSpeechToText` from `speech-to-text/testing/`.

### `IAgentSettingsStorePort` (`agent-settings-store.port.ts`)

`load(conversationId: string): Promise<AgentSettings | null>`, `loadMostRecent(): Promise<AgentSettings | null>` and
`update(conversationId: string, change: AgentSettingsChange): Promise<AgentSettings | null>`, where `change(own, mostRecent)`
returns the settings to store for the conversation or `null` to keep them, and the call resolves to the conversation's
settings afterwards. Every change of a profile goes through `update`, so concurrent changes to different roles of one
conversation (four `profiles.set` commands at once) all stay. Each conversation
has its own configuration: a channel that changes the configuration changes only the conversation (`conversationId`) it runs in.
`loadMostRecent()` returns the most recent configuration (highest `updatedAt`), allowing automatic inheritance for new conversations.
Implemented by `SqliteAgentSettingsStoreAdapter`: one `agent_settings` row per conversation (`applied_squad_id`,
`applied_squad_name`, `updated_at`) and one
`agent_profile` row per role of it; `update` reads both settings, calls `change` and replaces the conversation's rows in
one `SqliteTransactionService.run`. The `agent-settings` legacy importer moves `DATA_DIR/agent-settings.json` into them,
reading a flat entry of the earliest format (`agentId`, `modelId`... at the top level) as the same profile for every role
listed by `IAgentRegistryPort.listRoles()`.

### `IPreferencesStorePort` (`preferences-store.port.ts`)

`load(): Promise<Preferences>` and `update(change): Promise<Preferences>`: `change(current)` returns the changes to merge,
or `undefined` to leave the preferences, and the merge stamps `updatedAt`. The language the CEO detects is stored only
when `change` still finds none, so it never replaces one the user set meanwhile.
The preferences are global to the instance, shared by every conversation and channel. `Preferences.language` is the
language of the text agents write for the user. Implemented by `SqlitePreferencesStoreAdapter` in the one row of the `preferences` table, whose `update` runs read,
`change` and write in one synchronous database transaction; the `preferences` legacy importer moves `DATA_DIR/preferences.json`
of earlier versions into it.

### Persistence in `DATA_DIR`

`DataDirectoryService.resolve()` (`PathsModule`, `paths/services/data-directory.service.ts`) resolves `process.env.DATA_DIR`,
or `data/` at the repository root when it is unset or blank, and a relative value starts from the repository root.
The database module opens `DATA_DIR/arc.sqlite` with it, where the orchestrator's stores keep the agent settings, the
squads, the preferences, the agent sessions and the open work (see the `database` skill); the user's own skills stay in
`DATA_DIR/skills/`. Specs build file adapters with `dataDirectoryAt(path)` (`paths/testing/fixed-directories.ts`).
`WorkspaceDirectoryService` does the same for `WORKSPACE_DIR` (default `workspaces/`) and feeds `LocalWorkspaceAdapter`.

### 2. `IAgentRegistryPort` (`agent-registry.port.ts`)

Contract for resolving behavioral instructions and model specifications:

- `getSystemPrompt(agentRole: string, agentInterface: AgentInterface): string`: the prompt written for the interface of the session (`models/agent-interface.model.ts`: `tags` or `tools`)
- `getDefaultModel(agentRole: string): string | undefined`
- `getDefaultSessionMode(agentRole: string): 'resume' | 'new'`: the session of a delegation without an artifact and without the `session` attribute
- `getDisplayName(agentRole: string): string`: name shown in the footer (the role itself when unknown)
- `hasRole(agentRole: string): boolean`: validates the role of a delegation
- `listRoles(): string[]`: every registered role, in registration order
- `getDelegationContract(agentRole: string): DelegationContract`: `<delegate>` attributes the role accepts (`project`, `sessionMode`, which applies to delegations without an artifact; with one, `session` is accepted and ignored); empty contract for an unknown role
- `getReentryNote(agentRole: string, agentInterface: AgentInterface): string`: the note, written for the interface of the session, put before the prompt sent to a session resumed by that prompt (always a string, empty when the role has none)
- `isSystemPromptEveryTurn(agentRole: string): boolean`: role whose system prompt accompanies every user message (the CEO)
- Symbol of the same name: `export const IAgentRegistryPort = Symbol('IAgentRegistryPort');`

The implementation is `AgentRegistryService` from `AgentDefinitionsModule`, which resolves the
full prompts of each role, provides the re-entry notes and returns a generic prompt for
unknown roles.

### `IAgentSkillsPort` (`agent-skills.port.ts`)

The skills each role reads on demand (`models/agent-skill.model.ts`: `AgentSkillSummary` `{ name, description }`,
`AgentSkill` adding `content`):

- `list(role): Promise<readonly AgentSkillSummary[]>`: the catalog sent with the system prompt of a new session and with the prompt that reaches a resumed one
- `read(role, name, agentInterface): Promise<AgentSkill | undefined>`: the full skill, name matched case-insensitively, built for the interface of the reader's session
- `listAll(): Promise<readonly AgentSkillListing[]>`: every skill with its roles and whether it is built-in, for a role that writes skills (checked with `writesSkills`) and for a channel acting for the user
- `readAny(name)`: any skill with its listing, built for the first role that reads it on the tags interface, for a channel
- `writesSkills(role): boolean`: whether the role lists every skill, reads any of them and writes user skills
- `deleteUserSkill(name): Promise<boolean>`: deletes a user skill for a channel acting for the user, `false` when there is none (a built-in skill is never deleted; deleting a user skill that replaced one brings it back)
- `write(role, skill: AgentSkillInput): Promise<AgentSkillWriteResult>`: creates or replaces a user skill, `{ ok: false, error }` when refused

The implementation is `AgentSkillsService` from `AgentDefinitionsModule` (built-in skills plus the user's own; see the
`agent-definitions` skill). Specs use `StubAgentSkillsPort` from `testing/`.

### 3. `ConversationRuntimeService` (`services/conversation-runtime.service.ts`)

Keeps in memory the execution state of each conversation, identified by
`buildConversationKey(channelId, threadId)` (`utils/conversation-key.util.ts`, format
`channelId:threadId`). The key is the conversation and not the `SessionContext` because the session is only resolved
inside the queue:

- **Conversation agent**: a CEO `IAgentPort` created with `IAgentPortFactory.create(agentId)` on the first run and reused while `agentName === agentId`. When the turn asks for another agent, the previous port receives `closeSession()` and `disconnect()` (failures ignored) and a new one is created. The switch happens inside the CEO queue, after the turns that still use the previous port. `getCeoPort(conversationKey)` returns the current port or `undefined` before the first run;
- **Lifecycle and concurrency**: `beginTurn(conversationKey)` tracks `activeTurnsCount` and prevents premature expiration; `runOnCeo(conversationKey, agentId, work, onQueued)` guarantees mutual exclusion only on the use of the CEO port, releasing it while delegated agents run in the background;
- **CEO turn queue**: turns that arrive while the CEO is busy call `onQueued` and wait for the CEO port to be released, except when they enter the round through steering. New user messages are processed immediately by the CEO even with active delegations;
- **CEO steering**: `steerCeo(conversationKey, agentId, text)` injects the text into the CEO round in progress with `sendSteeringPrompt` and returns whether it was delivered (`injected`). It only tries when there is an active, non-cancelled turn, no other turn in the queue (`pendingTurns === 1`, so as not to jump ahead of an earlier message), the CEO port belongs to the requested `agentId` and advertises `supportsSteering` (read from the ACP `initialize`);
- **Agent receipts**: `addAgentReceipt`, `pendingAgentReceipts` and `acknowledgeAgentReceipts(conversationKey, count)` hold the `<agent_result>` receipts of delegations that reached an agent already at work until the CEO's next prompt reads them, outside the runtime that expires when idle, like the CEO notices;
- **Active delegations**: `registerDelegation(conversationKey, delegation)`, `unregisterDelegation(conversationKey, delegation)`, `getActiveDelegations()` and `findActiveDelegation(conversationKey, role)` keep the registry of specialists running in the background, indexed by role: a conversation runs one agent per role, in any project, and different roles run in parallel. `unregisterDelegation` ignores a delegation that has already been replaced by a newer one of the same role;
- **Direct shell commands**: `RunShellCommandUseCase.execute(conversationId, command)` runs `sh -c <command>` through `IProcessRunnerPort.run` with `cwd = IWorkspacePort.getBaseDirectory()`, outside the conversation queue and without any agent. It throws `ShellCommandDisabledError` unless `SHELL_COMMAND_ENABLED=true` (`ShellCommandConfigService`, disabled by default). The abort signal combines `SHELL_COMMAND_TIMEOUT_MS` (default 60 s) with a per-conversation `AbortController`; output beyond `SHELL_COMMAND_MAX_OUTPUT_CHARS` (default 8000) keeps its end. Returns `ShellCommandResult { command, exitCode, output, truncated, timedOut, cancelled }`. `CancelAgentTurnUseCase` also calls `RunShellCommandUseCase.cancel`, so `/cancel` stops a running command. `IAgentTurnPort` exposes `isShellCommandEnabled()` and `runShellCommand()`;
- **Cancellation**: `cancel(conversationKey)` cancels the CEO's `ActiveTurn` and all active `activeDelegations` of the conversation. Returns `false` when there is no work in progress;
- **Idle expiration**: with no turns and no delegations for the `SESSION_IDLE_TIMEOUT_MS` setting (default 30 minutes, read as each idle period starts), shuts down all agents (`closeSession` + `disconnect`), closing their tool sessions first. The `SessionContext` and its `agentSessions` remain in the store, and the next message resumes the ACP session with `loadSession`;
- **Shutdown**: `onApplicationShutdown` disconnects all agents (CEO and delegates). Requires `app.enableShutdownHooks()` in the bootstrap.

### 3b. `AgentProtocolService` (`services/agent-protocol.service.ts`)

Reads the response protocol agents follow, the `<final_response>` envelope (`constants/final-response.constant.ts`),
over the raw text the agent port hands over: `stream(handlers)` for the activities of a prompt as they arrive and
`finalResponse(written)` for the finished text. Everything about the envelope lives here, so the agent module
stays unaware of it.

### 4. `DelegationDetectorService` (`services/delegation-detector.service.ts`)

Interprets the protocol tags of the CEO's response and returns a `CeoDecision`. It recognizes
`<delegate>` and `<attachment>`, with name and attributes in any case and values in double
or single quotes, and hands the remaining text to `QuestionParserService` to recognize
`<question>`; any other tag stays in the text. Reading of tag attributes and body comes from
`utils/protocol-tag.util.ts`, shared by both parsers. The text outside the tags, with repeated blank
lines collapsed, is the `message` addressed to the user:

- `{ kind: 'delegate', message, delegations: [{ delegateToRole, projectName, taskSpec, sessionMode?, artifactId?, onBusy? }] }` when there is at least one `<delegate role="ROLE" project="folder" session="new|resume" on_busy="wait|interrupt">task</delegate>`. `role` is required and normalized to uppercase, `project`, `session` and `on_busy` (case-insensitive) are optional, and `taskSpec` is the tag content with surrounding whitespace trimmed, preserving markdown and stray `<`/`>`. Only the tag content reaches the agent;
- `{ kind: 'ask', message, questions }` when there is a `<question>`: questions to the user, whose answers return to the CEO in the same turn;
- `{ kind: 'reply', message, attachments }` when there is neither `<delegate>` nor `<question>`: the response to the user, which ends the turn. `attachments` lists the `path` attribute of each `<attachment path="...">description</attachment>` or `<attachment path="..." />`, in the order they appear;
- `{ kind: 'invalid', reason }` for a closing tag without an opening; `<delegate>` or `<attachment>` without closing or with another of the same name inside; an unknown or unquoted attribute; `<delegate>` without a valid `role`, with an empty `project`, `session` other than `new`/`resume`, `on_busy` other than `wait`/`interrupt` or without a task; `<attachment>` without `path`; attachments in a response that delegates; a malformed `<question>`; and questions together with `<delegate>` or with `<attachment>`. `reason` is written in English for the CEO to fix the response.
