# 06 — Web: scaffold and connection

**Model:** Sonnet 5.5 · **Effort:** medium · **Depends on:** 03 (runs in parallel with 04 and 05; testing against a live server needs 05)

## Goal

Create `packages/web`, a React + Vite + React Router + shadcn/ui + Tailwind app that follows the repository's TypeScript, lint and test conventions. It includes the layer that connects and authenticates to the server. The screens are placeholders; plan 07 builds the chat.

## Package setup

- Scaffold with the latest stable Vite React TypeScript template, then adapt it to the repository conventions: remove the template's own ESLint config, README and sample assets.
- **Dependencies:** `react`, `react-dom`, `react-router` (library mode with `createBrowserRouter`), `@agent-remote-control/protocol` (`workspace:*`).
- **Tailwind CSS v4** through `@tailwindcss/vite`.
- **shadcn/ui** initialized with `components.json`. Add `button`, `card`, `badge`, `collapsible`, `scroll-area`, `separator`, `textarea`, `tooltip` and `sheet`.
- **Dev dependencies:** `@vitejs/plugin-react`, `jsdom`, `@testing-library/react`, `@testing-library/user-event`, `@testing-library/jest-dom`, `eslint-plugin-react-hooks`, `eslint-plugin-react-refresh`.
- **`tsconfig.json`:** extends the base with `moduleResolution: "bundler"`, `jsx: "react-jsx"`, `lib: ["ES2023", "DOM", "DOM.Iterable"]`, `customConditions: ["source"]` and `types: ["vite/client", "vitest/globals", "@testing-library/jest-dom"]`.
- **`vite.config.ts`:**
  - `resolve.conditions: ['source', ...defaultClientConditions]`.
  - Dev proxy: `/ws` → `ws://localhost:3000` with `ws: true`, and `/health` → `http://localhost:3000`.
  - `build.outDir: 'dist'`.
- **Vitest project `web`:** `environment: 'jsdom'` and a setup file that imports `@testing-library/jest-dom/vitest`.
- **Scripts:** `dev`, `build` (`tsc --noEmit && vite build`), `ts`, `preview`. Root `yarn dev:web` runs the Vite dev server.
- **Root ESLint config:** add a block for `packages/web/**/*.{ts,tsx}` with browser globals, `react-hooks` recommended and `react-refresh/only-export-components`. Keep every existing rule.
  - Imports follow the same convention as the server: relative paths with the `.js` suffix, which Vite resolves to `.ts`/`.tsx`.
  - Rewrite the `@/` imports generated by shadcn to relative ones (set `components.json` aliases accordingly) and run `yarn format`. Do not disable rules globally to make generated code pass.
- **Coverage:** `src/components/ui/**` holds vendored shadcn code and is excluded from coverage in the `web` project. Everything else targets 100%.

## Structure

```text
packages/web/src/
├── main.tsx
├── router.tsx
├── connection/
│   ├── server-connection.ts             # IServerConnection interface
│   ├── websocket-server-connection.ts   # browser WebSocket implementation
│   ├── access-token.ts                  # read/store/clear the token
│   └── connection-context.tsx           # ConnectionProvider + useConnection()
├── pages/
│   ├── conversation-page.tsx            # placeholder in this plan
│   └── missing-token-page.tsx
├── components/ui/                       # shadcn (vendored)
└── lib/utils.ts                         # shadcn cn()
```

**`IServerConnection`:** `connect()`, `disconnect()`, `send(command: ClientCommand)`, `onEvent(listener)` and `onStatus(listener)`. The status is `'connecting' | 'open' | 'unauthorized' | 'closed'`. Components depend on the interface, so plan 3c of the roadmap adds a WebRTC implementation behind it.

**`WebSocketServerConnection`:**
- URL `${location.protocol === 'https:' ? 'wss' : 'ws'}://${location.host}/ws`. Sends `auth` first and reports `open` on `auth.ok`.
- On `auth.failed` or close code `4401`: report `unauthorized`, clear the stored token and do not reconnect.
- Otherwise reconnect with exponential backoff from 500 ms to a 10 s cap, resetting after a successful auth.
- Validate every incoming frame with `parseServerEvent`; drop invalid frames with a `console.warn`.
- Queue commands sent while not `open` and flush them after `auth.ok`.

**Access token:** on load, read `#token=` from the URL fragment, store it in `localStorage` and remove the fragment with `history.replaceState`. Wrap storage access in `try/catch`. Without a token, render `missing-token-page.tsx`, which explains that the link with the token is printed in the server log.

**Routes:** `/` and `/c/:conversationId` both render a layout with a connection status badge and the placeholder page.

## Tests

- **`WebSocketServerConnection`:** a fake `WebSocket` class installed with `vi.stubGlobal` (the browser WebSocket is an external I/O boundary) plus fake timers. Cover the auth sequence, `unauthorized`, the backoff schedule and its reset, the queued commands and invalid frames.
- **Access token:** fragment present or absent, storage throwing.
- **Provider and pages:** Testing Library with a fake `IServerConnection`.
